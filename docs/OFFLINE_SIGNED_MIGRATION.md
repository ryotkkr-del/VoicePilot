# P0-4｜署名済みZIPから旧bootstrapを移行するためのオフライン検証

開発者本人が秘密鍵と公開鍵固定ZIPを準備する手順は[開発者鍵・署名済みReleaseのオフライン作成](OWNER_SIGNED_RELEASE.md)を参照してください。鍵はGitHubやチャットへ送らないでください。

**状態：v0.23.13で検証コードと別フォルダへの準備機能を実装。開発者の本物の署名鍵、署名済み公式リリース、ユーザー所有Windows 11での移行実施は未完了。**

## なぜ通常の自動更新だけで移行しないのか

旧`voicepilot_bootstrap.py`はアプリ本体の更新時に上書きされないため、アプリを最新版にしても旧bootstrapに署名検証は追加されません。さらに公開鍵をGitHubのZIPやリリースページから取得するだけでは、同じ攻撃者が差し替えた鍵を信頼するおそれがあります。

今回の`app.signed_migration`は、開発者が**GitHubとは独立した方法で本人確認できる公開鍵と、そのSHA-256指紋**をユーザー側が入手した場合だけ、署名された候補ZIPを検証します。GitHub以外の経路が本当に信頼できるかは、ユーザー本人が別途確認する必要があります。

## 検証に必要な4つのもの

1. ローカルにある正規名`VoicePilot-vX.Y.Z.zip`のファイル（現時点の公式ZIPは**署名なし試作版**なので不可）。
2. 同じバージョンの`VoicePilot-vX.Y.Z.sig.json`（開発者が実際の秘密鍵でオフライン署名したもの）。
3. 開発者に独立して確認したEd25519の**公開鍵（64桁の小文字16進数）**。
4. 同じく独立して確認した、公開鍵の生32バイトに対する**SHA-256指紋（64桁の小文字16進数）**。

**秘密鍵・パスフレーズは一切入力しないでください。** 公開鍵と指紋は公開してもよい情報ですが、出所を第三者にすり替えられていないことが必須です。

### 1. インストールしない署名検証（先に実行）

VoicePilotのリポジトリフォルダで、通常権限のPowerShellから実行：

```powershell
.\.venv\Scripts\python.exe -m app.signed_migration `
  --zip "C:\path\VoicePilot-vX.Y.Z.zip" `
  --signature "C:\path\VoicePilot-vX.Y.Z.sig.json" `
  --public-key-hex "信頼済みの公開鍵64桁" `
  --fingerprint "独立して照合したSHA256指紋64桁"
```

確認する事項：ZIPのハッシュ・Ed25519署名・署名メッセージの版とリポジトリ・署名済みZIP内の必須ファイル・Chrome拡張の版・bootstrapリビジョン・**bootstrap内に固定された公開鍵が信頼済み公開鍵と完全一致すること**。

デフォルトでは検証用の一時フォルダ以外には書き込みません。自動ダウンロード、秘密鍵の生成、pipインストール、PC操作、Chrome操作、アプリ起動、設定ファイルのコピーは実行しません。

### 2. 別フォルダへ安全に配置する（明示的な承認が必要）

署名と鍵の確認が終わってから、Windows 11の**通常権限**で`--install-to`を指定します。

```powershell
.\.venv\Scripts\python.exe -m app.signed_migration `
  --zip "C:\path\VoicePilot-vX.Y.Z.zip" `
  --signature "C:\path\VoicePilot-vX.Y.Z.sig.json" `
  --public-key-hex "信頼済みの公開鍵64桁" `
  --fingerprint "独立して照合したSHA256指紋64桁" `
  --install-to "$HOME\VoicePilot-Signed"
```

- `MIGRATE`と入力した場合だけ、**現在存在していない新規フォルダ**へ準備します。
- 既存のVoicePilotフォルダおよびその配下には配置しません。既存フォルダ・ファイルを上書きしません。
- ZIPから読み込んだコードを検証処理中に実行しません。
- 設定、トークン、個人ファイル、`.venv`を旧環境からコピーしません。
- インストール後の依存関係セットアップ・GUI・音声・Chrome接続は**まだ未検証**であり、別途安全なテストが必要です。
- 失敗時は古い環境を変更せず、新しい導入先を作成しません。検証中の一時フォルダは削除を試みます。

**注意：** 新しいフォルダを作れたことは、更新基盤の実機安全性が証明されたことでも、旧バージョンを削除してよいという意味でもありません。旧版は残し、Windows実機の検収チェックが完了した後に別途判断してください。

## 今すぐはまだ実行できない項目

v0.23.13の通常のGitHub Release ZIPには、独立した本番開発者署名と、信頼済み公開鍵を埋め込んだbootstrapがまだありません。そのため、本ツールにそのZIPを指定しても**正しく拒否する**設計です。

開発者の本番鍵のオフライン管理、独立した指紋公表、公開鍵が固定されたリリースZIPの作成・署名・公開、その後の一度限りの安全な移行は未完了です。

この検証ツール自体も、未検証の配布元から取得して実行すれば信頼できません。信頼してよい初回配布経路の判断を**このツール自身の出力だけで代替しない**でください。

## 進捗の扱い

CIのテストはすべて使い捨てのテスト鍵とダミーフォルダのみを使用します。偽署名、ZIP改ざん、鍵指紋不一致、署名されたZIP内で異なる鍵が固定されたbootstrap、旧bootstrap、既存フォルダの上書き禁止、明示承認なしの配置拒否を確認します。

正式運用判定は`P0_INCOMPLETE`のままです。実際の署名鍵登録・配布と移行は、ユーザーの信頼境界を確認しながら別に進める必要があります。
