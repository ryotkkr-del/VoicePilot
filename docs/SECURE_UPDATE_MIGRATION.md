# P0-4｜開発者署名の検証と旧bootstrapの移行計画

**現在：署名検証コードとオフライン署名ツールは実装済み。開発者の本番鍵・署名付き公式リリース・既存インストールへの安全な移行は未完了。正式運用不可。**

## v0.23.10で実装したこと

- 新しい不変の`voicepilot_bootstrap.py`（`BOOTSTRAP_SECURITY_REVISION = 3`）は、公式GitHub ZIPのSHA-256と**開発者のEd25519電子署名**を検証し、どちらかが不正なら更新をステージングしません。
- 署名がない、別の鍵で署名された、ZIPのダイジェストとバージョンが合わない、署名ファイルの配信URLが異なる更新はすべて拒否します。**署名が使えない場合にGitHubのSHA-256だけで続ける処理はありません**。
- 以前の更新基盤が残した`pending.json`も、適用前に署名を再確認します。署名のない更新が新しいbootstrapへ引き継がれることはありません。
- 署名対象は次のASCIIバイト列。末尾にも改行が入ります。

```text
VoicePilot signed release v1
ryotkkr-del/VoicePilot
vX.Y.Z
VoicePilot-vX.Y.Z.zip
<lowercase 64-character SHA-256>

```

- 署名は生の64バイトEd25519署名を標準Base64（改行なし）にして、`VoicePilot-vX.Y.Z.zip.sig`という別ファイルでZIPと同じGitHub Releaseに置きます。
- テストでは一時的な使い捨てEd25519秘密鍵を使い、署名の正常系、偽装、欠落、バージョンやハッシュの差し替え、旧形式の未署名ステージ、暗号化された鍵ファイルの署名を検証します。**本番用の秘密鍵は一度もGitHub・CI・テストコードに置いていません。**

## 未設定の開発者公開鍵について

`voicepilot_bootstrap.py`内の`PINNED_SIGNER_PUBLIC_KEY_B64 = ""`は**意図的に空欄**です。開発者本人が信頼できる署名鍵を作成し、本人が確認した公開鍵を新しい不変のbootstrapに埋め込むまでは、**新しいbootstrapは自動更新を拒否**します。アプリ画面もこの状態を警告します。空欄を勝手な鍵で埋めたり、GitHubの更新情報から鍵を読み込んだりはしません。

### 開発者がオフラインで準備する手順（未実行）

1. GitHubのソースフォルダから離れた安全な保存先で、暗号化されたEd25519秘密鍵を生成します。例：OpenSSLの`genpkey -algorithm ED25519 -aes-256-cbc`を利用し、パスフレーズを設定します。
2. 公開鍵を取得してSHA-256の指紋を記録し、GitHub以外の確認可能な経路で鍵の所有者・指紋を検証します。**公開鍵は秘密ではありませんが、本物であることが重要です。**
3. 信頼した公開鍵を**一度だけ手動で新しいbootstrapに固定**します。秘密鍵とパスフレーズはチャット・GitHub・CIシークレット・配布ZIPへ送信しません。
4. 開発者の別PCで`python scripts/sign_release.py dist/VoicePilot-vX.Y.Z.zip --key C:/secure/private.pem`を実行すると、署名ファイルと公開鍵指紋が生成されます。パスフレーズは対話式に入力し、引数や環境変数に残しません。
5. ZIPと`.sig`を同じ公式GitHub Releaseに公開します。公開前に**独立して署名を検証**し、偽装・改ざんが検出できることを確認します。
6. 信頼済みのbootstrapに限って、署名済み更新の自動取得・適用を許可します。

## 旧bootstrapの移行

既存の`voicepilot_bootstrap.py`と起動バッチは、これまで意図的に自動更新の対象外です。したがって、**既存インストールのアプリだけをv0.23.10にしても、その旧bootstrapに署名検証は追加されません**。旧bootstrapが無署名更新を受け付ける問題も残ります。

安全な信頼基盤への移行には、署名者公開鍵・指紋を本人が独立して確認した後、旧フォルダを残しつつ別の新しいフォルダに信頼済みbootstrapを導入し、実機でのGUI・音声・Chrome・ロールバックを検証する一度限りの**明示的な手動移行**が必要です。現時点で移行は実施せず、ワンクリック自動で旧bootstrapを差し替えません。

## リリースと正式運用の状態

- CIの現在の公開ジョブは**テスト済みZIPのみを公開**します。開発者のオフライン秘密鍵はCIに渡さないため、**v0.23.10の自動公開ZIPに本番の開発者署名は付いていません**。
- 公開用の署名・実在する公開鍵・署名の最終検証・安全な初回インストールが揃うまで、**新しい署名必須bootstrapによる自動更新は使用できません**。
- 公開されたZIPのGitHub SHA-256と、開発者署名の独立検証は別物です。
- 鍵漏出・鍵紛失時は自動更新を停止し、本人確認済みの新しい信頼基盤を手動導入する方針です。未署名へフォールバックしません。
- P0-4の更新失敗、停電、ディスク満杯、バックアップ破損、スリープと再起動の反復試験、P0-5のWindows実機統合試験は未完了です。
