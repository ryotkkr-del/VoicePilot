# v0.23.19｜通常のVoicePilotも初期状態でPC操作禁止

**実機安全試験と本物の署名付き配布は未完了です。日常の重要な作業に使ってよいという判定ではありません。**

## 安全ロックの動作

- 通常GUIの起動直後は**PC操作がロック**されています。音声認識からの操作、テキスト指示、ハンズフリー、文章入力、長い自律作業、画面説明と外部連携などの開始を拒否します。
- 解除は**ローカルGUIに表示される「5分間だけ操作を許可」ボタン**を実際に押し、注意書きを読んで確認した場合だけです。音声指示、AI、設定ファイル、ブラウザ、起動時の状態復元では解除しません。
- 一時許可は最大5分で失効します。停止ボタン、Ctrl+Alt+Escの中止経路、ハンズフリーの音声による中止、ウィンドウ終了では許可を破棄します。
- エージェントは、開始前だけでなく、**高速命令・参照によるクリック・AIの各操作の実行境界で**許可を再確認します。文章入力の独立経路も同じ許可を要求します。
- 本物の署名者鍵が固定されていない現在のbootstrapでは、通常GUIの**バックグラウンド更新チェックを開始しません**。旧bootstrapを使った既存インストールではアプリ起動前の旧更新処理が残り得るため、これだけでは署名問題は解決しません。

## 安全ロックの限界

**許可ボタンを押したからといって実機で安全だと確認されたわけではありません。** これは単なる利用者の明示的な同意であり、5分以内なら操作機能が動きます。操作の対象確認と、危険操作の個別承認は依然として必要です。

- 一つのWindows入力/ブラウザ通信/アプリ起動が**すでに始まった後**は、許可失効や停止を検知してもその副作用を元に戻せません。
- 許可チェックとOSが実際に入力する瞬間の競合を完全に除去しているわけではありません。
- マイク・Chrome・Windowsの実機ではまだ検証していません。実機の停止遅延や誤入力率は不明です。
- 安全ロックは**配布ZIPの真正性を証明しません**。現在のGitHub自動配布ZIPは独立した開発者署名を持たない試作版です。出所が本当に信頼できるか、実際の配布物が改ざんされていないかをこの機能だけでは確認できません。

## 現在の推奨

1. **無理に通常GUIを起動しなくてよいです。** 正式運用のためには、本番署名と実機検収が先です。
2. どうしても音声認識だけ試したい場合は、独立した `try_voicepilot.bat` を使い、個人情報を含まないダミーのフレーズで試してください。ただし**このZIP自体も未署名**で、依存ライブラリの取得は明示同意を必要とします。
3. 通常GUIでPC操作を試すのは、バックアップと分離したダミー文書を準備し、どの操作が起こるかを理解できた場合だけにしてください。管理者として実行しないでください。

## 正式運用までに依然必要なこと

- 開発者本人の署名鍵を安全に作成・保管し、別経路で指紋を確認した**署名済み公式配布**を発行する
- Windows 11実機で停止・フォーカス切替・ブラウザ・マイク・GUI・復旧を試験する
- 実際の操作成功率・遅延・長時間稼働・スリープからの復帰を計測する

この開発は安全試験の代替にはならないため、P0の正式運用判定は未達成です。
