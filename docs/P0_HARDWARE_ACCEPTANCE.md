# P0-5｜Windows実機の安全検収手順（未合格）

**この手順は「正式運用OK」を自動判定するものではありません。** VoicePilot v0.23.12で追加した`app.p0_acceptance`は、固定された検査項目の状態のみ集めます。実機操作の自動実行、他アプリへの入力、ファイル編集、ネットワーク送信、録音、スクリーンショット収集は行いません。

## 実行前

- Windows 11、**通常のユーザー権限**で実行。管理者として実行しない
- 開発用に扱うのは**メモ帳の空のダミーファイルと自分で用意した公開テスト用Webページだけ**。実際のメール、パスワード、金融口座、課題、個人ファイルに操作させない
- ブラウザ拡張やOllamaの接続など、実際のVoicePilotの設定は本人が必要に応じて事前準備する
- 自動更新の実機試験は**本番インストールではなく**、独立した検証コピー＋バックアップで行う。署名鍵が未設定なら本番の自動更新は拒否される
- 本物の開発者署名鍵、信頼済みbootstrapへの一度限りの移行が完了していない限り、その他がPASSでも正式運用は不可

## 1. 読み取り専用の事前確認（自動・無操作）

リポジトリのフォルダから:

```bat
.venv\Scripts\python.exe -m app.p0_acceptance
```

`VERSION`、Chrome拡張のmanifestの版一致、Windows 11ビルド、管理者権限の有無、Python 3.11、**起動に使うbootstrapのrev.3以上か**、開発者公開鍵文字列が設定済みかを確認します。

**開発者公開鍵が文字列として存在しても、それが本人の本物の鍵であるとは確認できません。** 記録は`present_identity_unverified`となり、`production_approved`は常に`false`です。

## 2. 既存の隔離済み診断を利用する

```bat
.venv\Scripts\python.exe tests\windows_safety_check.py
```

この既存診断は通常権限、危険アクション拒否、プロセスと画面の識別、**一時フォルダのダミーファイルだけ**のリネーム・移動などを検査します。

必要な場合だけ、別コマンドでオプトインの実機テストを実行できます。各テストは開始前に明示的な`YES`を要求します。

```bat
.venv\Scripts\python.exe tests\windows_safety_check.py --interactive-notepad
.venv\Scripts\python.exe tests\windows_safety_check.py --interactive-microphone-benchmark
```

- メモ帳テストはダミーファイル名と正しいフォーカスを確認してから入力し、**表示された文字は本人の目視が必要**。ウィンドウの切替や拒否などが出た場合は合格としない
- マイクテストは固定フレーズを最大3回だけ録音し、認識の一致・不一致・時間を表示する。実際の操作は行わず、音声・認識全文も保存しない
- マイクモデルの重みがまだない場合にダウンロードされ得ることに注意。AIプロンプトや個人ファイルは外部送信しない

## 3. 手動の検収記録（任意）

```bat
.venv\Scripts\python.exe -m app.p0_acceptance --interactive
```

記録を**自分で指定した新しい場所にのみ**保存するには:

```bat
.venv\Scripts\python.exe -m app.p0_acceptance --interactive --output "%LOCALAPPDATA%\VoicePilot\p0-acceptance.json"
```

ファイルが既存の場合は上書きしません。内容は検査名と`PASS/FAIL/SKIP/NOT_RUN`だけで、Windowsのタイトル、ユーザーの声、ブラウザURL、画面写真、ユーザーファイルへのパスは含みません。パスの指定がない場合、報告ファイルは作りません。

**自己申告は証明ではありません。** PASSはその検査を本人が実際に安全なダミー環境で確認した場合だけ入力してください。できない操作はSKIP、未確認や中断はNOT_RUNとします。実機テストをしていないのにPASSを自動入力しないこと。

### 手動チェックの対象

| 項目 | ダミー環境での合格条件 |
|---|---|
| P0-1フォーカス切替 | 操作直前に別アプリへ切り替わったら入力を拒否する |
| P0-2 GUI停止・ホットキー停止 | 停止後の新規操作が行われないこと（実行済み操作は戻せない） |
| P0-2 音声停止 | ハンズフリーを明示的に有効にしたときのみ、終了/中断を確認 |
| P0-3 ダミー秘密値 | 架空の秘密値だけでクラウド送信・ログの扱いを検査 |
| P0-4 更新・復元 | 隔離した検証コピーのみ。更新中断・復元、設定保持を確認 |
| P0-5 メモ帳・マイク・Chrome | 同意したダミー環境で操作対象の同一性と停止を確認 |
| P0-5 スリープ・再起動 | 復帰後に未確認操作を続行せず、必要に応じ再確認する |

## 自動的に合格にならない理由

- GitHubのCIは自分のPCのマイク、UIA、Chrome、スリープ、USB、重要なアプリを実際に操作した証拠にはならない
- 手動テストの自己申告だけでは開発者署名鍵の所有・発行・本人確認を証明できない
- 一時ファイル上の試験は、日常の個人ファイルを無人で安全に操作できることを保証しない
- 失敗やSKIPが一つでもあればその項目は未達成であり、`production_approved: false`のままとする

検査を実施した環境の設定やバージョン差異を把握したうえで、[正式運用ロードマップ](ROADMAP_PROGRESS.md)の各P0ゲートを**項目ごとに別途審査**します。
