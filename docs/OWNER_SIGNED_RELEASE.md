# P0-4｜開発者本人のオフライン署名鍵・署名付き配布物の準備

**v0.23.14：鍵の生成・署名候補ZIPの生成・検証のコードを追加しました。本物の開発者鍵は未設定、公式Releaseは未署名の試作版です。**

この手順はVoicePilotの開発者本人が信頼するWindows PCで、事前に確認したソースから作業するためのものです。**秘密鍵やパスフレーズをChatGPT、GitHub、CI、ZIP、メール、Discordに送らないでください。** 鍵はオフラインで扱います。公開鍵の指紋はGitHubとは独立した方法で本人から利用者へ伝える必要があります。

## 現在の設計が守る境界

- 開発用の`scripts/owner_release.py`は公開ソースのチェックアウトから実行します。通常のVoicePilot配布ZIPには含まれません。
- 鍵は**ソースリポジトリの外**、そのPCの本人だけがアクセスできるフォルダに保存します。暗号化したPKCS8のEd25519秘密鍵のみ使用します。
- 作業はローカルのファイルだけで完結します。GitHub APIやクラウドに問い合わせず、PR・リリース公開も行いません。
- ZIPのソース構成、`VERSION`、Chrome拡張の版、元bootstrapがrevision 3以上で公開鍵欄が空であることを確かめます。
- ZIPから一時フォルダに展開したbootstrapの**公開鍵の定数値だけ**を書き換えます。元ZIP、ソース、既存インストールは一切変更しません。
- 出力されるZIPと`.sig.json`は、オフラインの独立署名検証器`app.signed_migration`で再検証した後、**新しい別フォルダへだけ**保存します。上書きは拒否します。
- テストは使い捨て鍵のみ。未署名ZIP、異なる鍵、ハッシュ改ざん、パス不一致、秘密鍵配置違反、旧bootstrapの拒否を検証します。

## 開発者が準備する手順（まだ実施していない）

### 1. 自分だけが管理する秘密鍵用のフォルダを用意する

信頼できるPCのローカルストレージで、本人だけが読める保存先を用意します。クラウド同期・リポジトリ・公開共有フォルダは避けます。可能ならこの時点でネットワークを切断してください。インストール済み依存関係の更新が必要な場合は、ネットワーク切断前に環境を整備します。

コマンド例はPowerShellです。VoicePilotの**ソースリポジトリ**のフォルダで実行します。

```powershell
.\.venv\Scripts\python.exe scripts\owner_release.py new-key --key "D:\private\voicepilot-ed25519.pem"
```

コマンド内で秘密鍵のパスフレーズを**2回、非表示で**入力します（16バイト以上）。秘密鍵ファイルが既に存在する場合、作成を拒否します。生成された公開鍵の16進数とSHA-256指紋を表示するので、**公開情報だけ**を本人が別経路で確認できる形で保存します。

**秘密鍵そのものやパスフレーズをGitHub、チャットへ貼り付けないでください。** パスフレーズはプロセスのコマンドライン引数や環境変数に含めません。

### 2. ソースを確認し、リリース候補ZIPを作成する

署名するコードを自分で監査してから、次のコマンドで同じバージョンのZIPを作成します（例は`vX.Y.Z`です）。

```powershell
.\.venv\Scripts\python.exe scripts\build_release.py
```

コードが変更されている場合はテストも行ってください。**署名はコードの安全性を自動で証明しません。** 署名した人と、署名したZIPが変更されていないことを検証する仕組みです。

### 3. 公開鍵を固定した署名付き候補ZIPを作る

```powershell
.\.venv\Scripts\python.exe scripts\owner_release.py prepare `
  --source-zip "dist\VoicePilot-vX.Y.Z.zip" `
  --key "D:\private\voicepilot-ed25519.pem" `
  --output-dir "D:\release\VoicePilot-vX.Y.Z-signed"
```

パスフレーズは対話式で入力し、出力先は**存在しない新しいフォルダ**を指定します。生成されるものは以下の2ファイルです。

- `VoicePilot-vX.Y.Z.zip`：**同じ公開鍵を固定した**新bootstrapを含む配布ZIP
- `VoicePilot-vX.Y.Z.sig.json`：ZIPとバージョン等を束縛するEd25519の署名データ

両方のファイルを配置した後にも独立署名とZIP内容を検証します。出力先に既存ファイルがあれば拒否します。生成された公開鍵・指紋は**本人確認済みだと自動的には扱いません**。利用者へ独立に確認できる方法を準備してください。

### 4. 署名を確認してから、別フォルダへ移行する

`python -m app.signed_migration`で、ZIP・署名・**独立して本人確認した公開鍵と指紋**を指定し、まず**検証のみ**を実施してください。実際の導入は、その検証に成功した場合に限り、通常権限のWindows 11で`--install-to`を使い、新しい別フォルダへ配置します。詳細は[オフライン移行手順](OFFLINE_SIGNED_MIGRATION.md)を参照してください。

旧VoicePilotフォルダ、設定、トークン、ユーザーファイルは自動移行しません。

## GitHubの自動公開についての重大な注意

現在のGitHub Actionsは`main`への反映時に**未署名の試作ZIP**を自動公開します。**一度公開済みの同じタグでZIPを署名済み版に差し替えてはいけません。** 元の未署名ZIPと、公開鍵固定のために内容が変わったZIPは異なるハッシュです。後から別の`.sig.json`だけ添付しても元の公開ZIPの署名にはなりません。

**本番署名済み公式Releaseを発行する前に必要な工程：**

1. 未署名版の自動公開を停止する、または未公開の新しいバージョンに切り替えて公開フローを凍結する。
2. 独立して確認した開発者鍵を用い、その**未公開バージョン**のZIPと署名を同時に準備する。
3. 公開前にSHA-256、署名、ZIP内の公開鍵、バージョン、既存タグがないことを確認する。
4. 鍵を持たないCIに秘密鍵を渡さず、本人の明示操作でZIPと署名を公開する。
5. 旧bootstrapからの一度限りの安全な移行を実施し、Windows実機で正常系・改ざん・中断・復旧・停止を検証する。

このうち**開発者鍵の本人確認・署名済み公式Releaseの発行・実機試験は未実施**です。v0.23.14も本番配布には合格していません。コード追加だけをもってP0-4を合格扱いにしません。
