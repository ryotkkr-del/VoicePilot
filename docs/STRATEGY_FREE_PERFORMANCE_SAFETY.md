# VoicePilot｜無料・高性能・安全を両立するための方針

最終更新: 2026-11-16  
対象: `main` の v0.23.22（プロトタイプ）

## 結論

VoicePilot は、**ローカル処理を標準にして有料APIを必須にしない**。同時に、PCへ実際の効果を与える機能は、性能や便利さより安全ゲートを優先する。  
「すべての操作を無制限に自動化」「クラウド品質を無償かつ無審査で使う」「実機検証なしに安全と言う」は両立しないため、正式運用まで段階的に機能を開放する。

## 3つの約束

| 目標 | 方針 | 現時点の差分 |
|---|---|---|
| 無料 | 日常利用の標準経路はローカルASR + Ollama + ローカル橋渡し。Gemini等のクラウドは任意・明示設定・都度確認であり、必須にしない | コードはライセンス未選定。公開されていても、再利用・再配布が許可された「無料ソフト」ではない |
| 高性能 | 軽量な定型コマンドを最優先し、AI計画・画面理解は必要時だけ使う。推測ではなく、代表的なWindows実機で遅延・成功率・メモリを測る | CIと少数のマイク診断はあるが、100件以上の実機評価・長時間測定は未実施 |
| 安全 | 起動時ロック、短時間の明示許可、停止、対象確認、最小限のログ、クラウド開示ごとの同意、署名済み更新を必須にする | 多くはモックCIで一部実装。実機の停止・フォーカス競合・署名済み配布は未達 |

## 製品原則

1. **ローカル・デフォルト。** 音声・操作計画・画面情報は、可能な限り端末内で処理する。外部送信は明示的な機能選択と目的別の確認がある場合だけ行う。
2. **安全が性能より上位。** 停止、許可失効、対象不一致、データ開示の不確実性があれば失敗として止める。処理済みの入力や送信済みのクラウド要求は巻き戻せないことをUIに明示する。
3. **能力は危険度で分ける。** 読み取り・候補表示 → 可逆で低影響な操作 → 送信・削除・権限変更など高影響操作、の順に扱う。高影響操作は常にローカル確認を要し、無人実行しない。
4. **測れない性能主張をしない。** 「高速」「高精度」は、対象PC、モデル、データ、p50/p95遅延、成功率、失敗理由を添えた測定結果でのみ主張する。
5. **無料はサプライチェーンを犠牲にしない。** 依存関係、モデル、拡張機能、更新ZIPの出所を検証する。安価・無料でも未署名更新を自動適用しない。

## 直近の優先順位（P0を先に完了）

### P0-A: 実機安全ゲートを完了する

正式運用の前提として、通常権限の隔離Windows 11環境で次を実施・記録する。

- ダミーのメモ帳、公開テストページ、テスト用Chromeプロファイルだけで、フォーカス切替時に操作を拒否することを確認する
- GUI停止、`Ctrl+Alt+Esc`、音声停止、5分許可の失効、スリープ復帰、Chrome再起動で、新規操作が継続しないことを確認する
- クラウド画面本文・画像の各送信について、確認拒否、対象変更、許可失効が送信前に拒否されることを確認する
- 実行済み入力・送信済み要求が取り消せない場面は「失敗」ではなく残余リスクとして記録し、無人利用対象から外す

**完了条件:** `docs/P0_HARDWARE_ACCEPTANCE.md` のP0項目が、実施環境・版・結果・既知の失敗とともに手動記録される。失敗、SKIP、未確認がある項目は正式運用対象に含めない。

### P0-B: 配布と更新を真正な署名へ移行する

- オフラインで開発者鍵を生成・保管し、公開鍵フィンガープリントをGitHub以外の独立経路でも公開する
- **未公開の新バージョン**だけを署名し、ZIP・署名・公開鍵・検証手順をセットで配布する
- 新規導入と既存導入の双方で、別フォルダ移行、更新中断、復旧、ロールバックを隔離環境で実機検証する
- CIは未署名ZIPを「stable」として公開しない。署名資材がなければ、配布を止めるか、試験用であることを資産名・説明に明記する

**完了条件:** ピン留め済み鍵で検証できる公開リリースを、実機で検証してから発行する。鍵が未設定・署名不正・復旧不能なら自動更新は停止する。

### P0-C: 公開プロジェクトとしての基本を整える

- ライセンス方針（例: 利用条件、再配布、商用利用、モデル重みの条件）を決め、`LICENSE` と依存物のライセンス一覧を追加する
- `SECURITY.md` に脆弱性の連絡窓口、サポート対象版、秘密情報をIssueに書かないルール、修正公開方針を置く
- 依存関係を定期更新し、変更前にテストする。ActionsとPython依存のバージョンをレビュー可能な形で固定・監査する
- リリース用権限は最小化し、署名鍵をリポジトリ・ログ・PR実行環境に置かない

## 性能と機能のロードマップ（P0完了後）

### P1: 実測によるローカル体験の改善

1. **評価基盤:** 最低1台の基準PCと、低・中・高性能の3クラスで、100件以上の日本語コマンドを評価する。認識、解釈、実行を分けて成功率とp50/p95を記録する。
2. **高速経路:** 「メモ帳を開く」「戻る」「スクロール」など、許可済みの定型・低影響操作は、クラウドも大規模モデルも呼ばない決定的パーサで処理する。
3. **遅い経路の隔離:** AI計画、OCR、画面説明は明確なUI状態と中止可能な待機を持たせる。時間超過・Ollama停止・メモリ不足では副作用を起こさず、説明可能な失敗にする。
4. **資源上限:** モデルの常駐・自動ダウンロード・バックグラウンド更新をデフォルト無効にし、利用者がストレージ・メモリ・ネットワークを選べるようにする。

**P1の成果物:** 再現可能なベンチマーク手順、匿名化した集計結果、サポートPC要件、採否の性能しきい値。

### P2: 安全な範囲で操作対象を増やす

- まず読み取り専用の説明・候補表示を増やし、実行は毎回プレビューから本人が選ぶ
- 送信、削除、ファイル移動、設定変更、認証画面、支払い・契約に関わる操作は原則として自動化対象外にする
- 新しいアプリ対応は、対象識別、停止、失敗時の不実行、回帰テスト、実機テストを1セットとして追加する
- クラウド機能はローカルモードと同等の安全境界を下回らない。画面マスクの精度が実証されるまでは、機密画面を送らない

## リリース判定

| 区分 | 提供してよい範囲 | 必須条件 |
|---|---|---|
| 試用版 | マイクのみ、読み取り、候補プレビュー、隔離されたダミー操作 | 明確な「プロトタイプ」表示、ローカル優先、データ保存なし、実行前同意 |
| 限定運用 | 低影響の明示操作 | P0-A/B/C完了、署名済み配布、実機結果の公開、残余リスクの明示 |
| 正式運用 | 日常的な音声支援 | P0全項目の継続的合格、長時間・障害・更新復旧の実績、サポート範囲と禁止操作の公開 |

高性能のために安全確認を飛ばさず、無料のために更新の真正性を妥協しない。P0が未完了の間、VoicePilot は「便利な実験」であり、重要データを扱う自律PC操作ツールとしては提供しない。

## 次の3件

1. 署名者鍵・独立フィンガープリント・未公開版の署名済みリリースを用意し、隔離実機で移行と復旧を試験する。
2. `P0_HARDWARE_ACCEPTANCE.md` に従い、ダミー環境で停止・フォーカス競合・クラウド開示拒否を実機検証して結果を記録する。
3. `LICENSE`、`SECURITY.md`、依存関係/Actionsの監査方針を追加し、公開プロジェクトの配布条件を明確にする。
