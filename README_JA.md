# VoicePilot v0.15 — 操作の手数を減らすUX更新

**固定要件：自由度を高く・無料で利用・できればWindows PC全体を操作。** v0.14のコード・安全対策・ChatGPTへの下書き連携を継承しています。新しいクラウドサービスや常駐モデルは追加していません。

## 今回変更したこと

1. **操作中に次の音声指示へ移りやすく：** AIが操作中または文字起こし中の「話す」ボタン（`Ctrl+Alt+Space`）を「中断して話す」に変更。押すと旧処理の中止を要求し、**旧処理が終了した後で**新しい録音を開始します。すぐ話し始めるのではなく、画面が「聞いています」になるのを確認してください。もう一度押すと録音の予約を取り消せます。
2. **小さい画面でも設定・ログに到達できる：** 画面全体をスクロール可能にしました。設定を開いてもウィンドウの大きさ・位置を強制変更しません。Windows 125%〜200%などの拡大表示でも、画面外に隠れた項目へ移動しやすくなります。ログ領域のホイール操作はログ自身をスクロールします。
3. **ボタンが今できることを伝える：** 音声認識中や操作中は「実行」「ChatGPT下書き」を無効化。何も起こらない連打を防ぎます。停止と予約済み録音の取り消しは別操作にしました。
4. **入力途中の文章を壊さない：** Whisperの文字起こしに時間がかかっている間、入力欄へ別の指示を書いた場合は、後から到着した認識結果で上書きしません。認識した内容は一時的な操作ログに表示されます。
5. **ChatGPT送信と誤認しない表示：** UI上の「ChatGPTへ」を「ChatGPT下書き」に変更。送信は引き続きユーザーが行います。

## 普段の使い方

- **音声入力：** `Ctrl + Alt + Space` または「話す」。話し終わると自動認識（設定でオフも可）。
- **操作中に新しい指示へ切替：** 同じショートカットを押すと中断要求→旧処理の終了後に新しい録音を開始。切替待ちは「録音予約を取消」で取り消せます。
- **すべて中止：** `Ctrl + Alt + Esc` または「停止」。進行中の外部操作を必ず巻き戻せるわけではありません。
- **聞き間違い：** 入力欄に表示された認識結果を直して「実行」。音声入力後に別の文章を書いていた場合は、その文章を保護します。
- **画面が小さい場合：** ホイール／スクロールバーで下へ。設定は「設定」から開閉できます。

## インストール／更新

1. ZIPを適当なフォルダへ展開し、`setup_and_run.bat` を実行してください。初回はPythonの依存ライブラリや音声モデルの取得が必要です。Python 3.11、必要に応じてOllamaが必要です。
2. Chromeの拡張機能管理 `chrome://extensions/` で旧VoicePilot拡張を無効にし、v0.15に同梱の `chrome-extension` を「パッケージ化されていない拡張機能を読み込む」で追加します。
3. Windows側の「接続コードをコピー」でペアリングします。旧版と同時にアプリを起動しないでください。
4. 従来の設定ファイルは `%APPDATA%\VoicePilot\config.json` に保持されます。ZIPの更新で削除・上書きしません。

## 検証と限界

- Pythonユニットテスト **147件**、Node.js疑似DOMテスト **9ファイル**、JavaScript構文チェックが通過。
- Windowsなしの仮想画面（800×768）で、設定開閉後もウィンドウが560×600のままで、下部までスクロール可能なことを確認。
- **Windows実機でのマイク入力、ホットキー、アプリ操作、CPU/RAM負荷、操作成功率はまだ未測定です。** 中断は協調的に行うため、進行中のAI通信や外部操作を瞬時に停止できるとは限りません。音声の「中断して話す」は旧タスクを中断してから録音する方式で、同時録音ではありません。
- セキュリティ上、送信・削除などは従来の確認を維持します。新機能は既存の安全性の保証を強めるものではありません。

# VoicePilot v0.14 — 「それ」が安全に通じる文脈理解の改善

## v0.14で変えたこと

- **直前の対象を、今の画面から探し直す：** 「それを押して」「そのボタンを押して」「さっきのボタンをクリックして」の短い指示では、以前のボタンIDを使い回しません。現在のChrome DOMまたはWindows UI Automationで、同じ要素を**一意に**特定できる場合に限ってクリックします。
- **曖昧さを放置しない：** 同名の要素が複数ある、別タブ・別画面に移動した、ボタンの役割が変わった、前の対象から10分以上経った場合は、勝手にクリックせず確認を求めます。

- **既存の安全性を継承：** 送信・削除などの高リスク操作は従来どおり確認。ChatGPT Web下書き連携も維持し、OpenAI API・Codex・Workを自動呼び出しません。

# VoicePilot v0.13 — 安全確認の精密化（v0.12を継承）

**固定の要求は3つだけ：自由度が高い・無料で使える・できればPC全体。** 今回は通常操作の煩わしさを増やさず、**確認した対象と実行される対象がズレる問題**を抑える改善です。Codex/Work/OpenAI APIは利用しません。

## v0.13 の変更（新機能の追加ではなく動作改善）

1. **URL変更時は古いクリックを無効化：** Chromeが同じタブ・同じDOM要素のまま別ページへ遷移した場合も、観測時のページと違えば実行を止めます。URL全体をAIに渡さず、Chrome拡張機能内部で短いフィンガープリントを保持します。クリック後の結果確認とは別の、**クリック直前の安全確認**です。
2. **ボタンの役割変更を再確認：** 観測後にボタンがフォーム内やダイアログ内へ移った場合、元の承認を流用せず停止します。見た目の名前が変わらない場合にも対応します。
3. **フォーム関連の操作判定を改善：** `<button form="...">` のようにフォーム外から送信するボタンや、フォーム内のチェックボックスも変更操作として扱います。通常の入力欄へのフォーカスだけで確認が増えすぎないよう区別します。
4. **機密欄の見落としを軽減：** HTMLの `aria-labelledby` などから取得したラベルが「認証コード」等の場合も、音声操作の候補から除外します。既存の入力内容はAIに送信しません。
5. **読み取り専用欄を保護：** 入力対象が読み取り専用なら、変更操作を拒否します。
6. **不要な確認を削減：** `OK` は確認対象のまま、英語の `Look` や `Book` に含まれる偶然の `ok` には反応しないよう改善しました。

# VoicePilot v0.12 — 安全性の強化（既存のv0.11を継承）

**製品の要求は3つだけです。** ①自由度の高いPC操作、②無料で継続利用、③できればWindows全体での操作。今回のアップデートはその実現を妨げず、**意図しない送信・上書き・クリック**を減らすためのものです。Codex/Work/OpenAI APIへの自動接続は追加していません。

## 変更内容

1. **重要操作を対象情報から判定:** Chromeのフォーム内ボタン、送信ボタン、ダイアログ内ボタン、別サイトへのリンク、および削除・支払・投稿などの表示を持つボタンは、実行前に許可を求めます。単なるラベル一致だけに依存しません。
2. **Webページ由来の不正な指示への対策:** ユーザーが指定していない別サイトをAIが開こうとした場合、サイトURLを示して確認します。ユーザーが直接指定したドメインや現在のサイト内移動では基本的に確認を増やしません。ページの文章はAIへの命令ではありません。防御の完璧さを保証するものではありません。
3. **既存の入力を保護:** Chromeの文字入力欄に既に値があれば上書きを確認します。承認中に入力欄の状態やリンク先が変化した場合は実行しません。
4. **機密情報をAIに渡さない:** Webのパスワード・認証コード・APIキー・カード情報欄を候補から除外。テキストエディタや入力欄に入力済みの内容を、操作候補のラベルとして送らないよう修正。Windows UI AutomationのEdit要素も既存文字列の代わりに「入力欄」と表示します。
5. **盲目的な操作の承認:** UIの構造で対象を確定できない画像座標操作、Windowsの任意テキスト入力、貼り付け（Ctrl+V）、Enter、保存、およびファイル移動・改名は明示的に確認します。
6. **承認画面を信用できる情報で作成:** AIが作った説明文ではなく、画面で観測した操作対象・サイト・操作種類を表示します。入力文字列、URLのクエリ等は承認画面に出しません。
7. **接続コードの後片付け:** Chrome拡張のペアリングコードをコピーして60秒後、クリップボードがまだ同じコードなら消去。後からコピーした別の文章は消しません。
8. **速度面:** 画像解析や新しいAIモデルの常駐は増やしていません。画像座標の承認判定で無駄にWindows UI Automationを走らせないようにしました。

## 使い方と更新

1. v0.11をバックアップとして残し、v0.12を別フォルダに展開します。両方は同時に起動しないでください。
2. Windows 11で `setup_and_run.bat` を実行。従来どおり無料Ollamaを標準に使用できます。初回にはPython・必要なライブラリ・モデルのダウンロードが必要な場合があります。
3. Chromeの `chrome://extensions/` で、旧版拡張を無効にして、v0.12の `chrome-extension` フォルダを読み込んでください。
4. VoicePilotの接続コードをコピーして拡張機能とペアリングします。通常のChrome/Windows操作は従来どおり。`Ctrl + Alt + Space` で録音、`Ctrl + Alt + Esc` で停止。
5. 承認を求められたら、対象のウィンドウ・サイト・ボタン名を見て許可するか判断します。心当たりのない操作は「いいえ」にしてください。

## 何がまだ危険・未検証か

- 音声認識を間違える可能性は残ります。高リスク操作は承認が必要です。**承認した操作が必ず安全になるわけではありません。**

# VoicePilot v0.11 — 精度・操作対象の認識改善

v0.10からの**精度改善**版です。これまでのWindows全体の操作、Chrome拡張、無料ローカルAI、任意のGemini、音声結果報告、ChatGPT Webへの下書き受け渡しを維持します。**Codex・WorkとOpenAI APIは利用しません。** 今回は機能の量を増やすのではなく、曖昧な対象を勝手に選ばないことと、操作成功率の改善に集中しました。

## 今回の改善点

1. **低信頼の音声認識結果を抑止:** ほぼ無音の録音は推論前に除外し、Whisperの `no_speech_prob` が非常に高く、かつ `avg_logprob` が低い区間のみ捨てます。通常の小声を一律に捨てないため、単純な音量閾値だけでは判定していません。用語ヒントも短い固有名詞リストに変更し、無音から指示文を捏造する傾向を抑えます。
2. **ボタン取り違えの防止:** Chromeはスナップショットで観測したボタンのラベル・種類・役割をクリック直前に再検査。対象が変化したり、別の要素に覆われていればクリックせず停止します。Windows UI Automationでも観測時のコントロール情報と現在を照合します。
3. **曖昧なタブ・ウィンドウ選択を禁止:** 一部一致が複数あるときは最初の候補を勝手に選びません。完全一致で一つに絞れる場合はそれを使います。
4. **操作候補のJSON不正を一度だけ再生成:** LLMの出力形式が壊れた場合に限り、操作の実行前に再生成を試します。ネットワークエラーや実行済みクリックを無条件に再試行しません。
5. **Chromeの操作対象の見つけやすさ:** `aria-labelledby` やネイティブラベルも利用し、ページ内で見つけられる入力欄を増やしました。通常ページが動かない場合だけ、ページ内のスクロール領域を探して動かします。
6. **名前が空の要素:** 正体を判定できないボタンは無条件でクリックせず、確認を求めます。

5. `Ctrl + Alt + Space` で音声入力、`Ctrl + Alt + Esc` で中止。ChromeやWindowsの操作、ChatGPTへの下書き受け渡しはこれまでどおりです。

# VoicePilot v0.10 — ChatGPT Web連携（Codex・Work利用枠を使わないモード）

VoicePilot v0.9の既存コードを引き継ぎ、**ChatGPTのWeb画面に質問を渡す機能**を追加しました。従来のWindows/Chrome音声操作、Ollama・Gemini切替、音声読み上げは維持します。

> **重要:** この連携は **ChatGPTのWeb画面に「下書き」を用意するだけ**です。送信は利用者自身が確認して行います。ChatGPTの回答をVoicePilotが自動取得・操作に反映する機能はありません。ChatGPTアカウントの認証情報をVoicePilotに渡す必要はありません。Windows実機の統合テストは未実施です。

## 設計の理由：Codex/Work枠を温存する

2026年11月時点、OpenAI公式の `Sign in with ChatGPT` を使って自作アプリから直接モデルに推論を依頼すると、**ChatGPTのWork/Codexと共通の利用枠または承認済みクレジット**が使われます。今回の要求は「なるべくCodex・Workの利用枠を使わない」なので、この認証方式を今回は実装していません。

- **PC操作の判断**：従来どおりOllama（完全ローカル、追加API料金なし）／任意のGemini（無料枠には上限あり）を使用。
- **ChatGPTへの相談**：ChatGPTのWeb画面を開き、ユーザーが明示的に話した／入力した文章を下書きにセット。送信は利用者本人が行う。
- **VoicePilotがChatGPTのAPI・Codex・Workを呼び出す処理**：**なし**。
- 通常のChatGPTの会話にも、ご利用プランの通常の利用制限はあります。VoicePilotがWork/CodexのAPI利用枠を消費しない、という意味です。

参考： [OpenAI公式 — 他のアプリでChatGPTプランを使う場合の枠](https://help.openai.com/en/articles/20001542-using-your-chatgpt-plan-in-other-apps-and-sites)

## 使い方

### A. 声で直接ChatGPTに質問を渡す

1. WindowsでVoicePilotを起動し、`Ctrl + Alt + Space` で話す。
2. 「**チャッピーにPythonの例外処理を教えて**」または「**ChatGPTでこの式を解説して**」などと話す。
3. Chrome拡張が接続されていれば、ChatGPTのタブを開き、**既存の下書きが空の場合のみ**、質問を入力欄に用意します。
4. **画面で質問を確認し、自分で送信**してください。VoicePilotは回答を勝手に取得しません。

「**ChatGPTを開いて**」ならページだけ開きます。

### B. テキスト入力欄から渡す

1. VoicePilotの「認識した指示」欄に質問を書く（音声認識後の文章を修正してもOK）。
2. 通常の `実行` ではなく **`ChatGPTへ`** を押す。
3. Chrome上の下書きを確認して送信する。

`ChatGPTへ` ボタンを押した場合は、先頭に「チャッピーに」を付けなくても渡せます。

### C. Chrome拡張が未接続・ログイン待ち・下書きが埋まっている場合

- 文章を**クリップボードにコピー**してChatGPTを開きます（既存の下書きは上書きしません）。
- ChatGPT入力欄に貼り付け、内容を確認して送信してください。
- ChatGPTのUI変更などで入力欄を見つけられない場合にも、この安全な代替操作を使用します。

## 初回セットアップ（Windows 11）

1. ZIPを展開し、`VoicePilot-v0.11` フォルダを用意。旧バージョンは削除せず、両方を同時起動しない。
2. [Python 3.11](https://www.python.org/downloads/) と必要に応じて [Ollama](https://ollama.com/) をインストール。
3. ローカルAIで通常のPC操作も行うなら、`ollama pull gemma3:4b` を一度実行しOllamaを起動。
4. `setup_and_run.bat` を実行。初回はライブラリをインストールし、初回音声認識時にWhisperモデルをダウンロードします。
5. Chromeで `chrome://extensions/` を開き、デベロッパーモードを有効にして、同梱の `chrome-extension` を「パッケージ化されていない拡張機能を読み込む」で追加。
6. 拡張機能ポップアップにVoicePilotの「接続コード」を入力して接続。**旧バージョンのVoicePilot拡張機能は無効に**してください。
7. ChatGPTのWebサイトには、必要に応じて通常のブラウザ操作でログイン。

拡張機能を使わなくても、「ブラウザを開く + 質問をコピーする」手動連携は使えます。

## プライバシー・動作の制限

- ChatGPTのログイン情報やCookie、アカウントトークンをVoicePilotは取得・保存しません。
- ChatGPTへの**送信ボタンは自動的に押しません**。回答の自動抽出・スクレイピングも追加しません。
- PC上の画面全体・ファイル・クリップボードの内容を、**暗黙にChatGPTへ送信することはありません**。明示的に入力した質問文のみ下書きに渡します。
- Chrome拡張には、従来のPC操作のために `<all_urls>` の閲覧権限があります。信頼できるサイトでのみ使い、不用意に入力されたパスワードやファイルを操作しない設計を維持しています。
- ChromeのUIが変更された場合、文章が自動入力できないことがあります。その場合はクリップボードにコピーされるので、手動で貼り付けてください。
- 音声によるPC操作は、依然として通常の権限・アプリのUIに制限されます。
- 実機でのChatGPT画面入力、発話認識精度、CPU/RAM負荷は未検証です。

## 新規・変更したコード

- `app/chatgpt_handoff.py`：明示的な音声指示の判別、Chromeへの受け渡し、クリップボードへの安全なフォールバック。
- `app/main.py`：テキスト欄に `ChatGPTへ` ボタン追加。音声指示もモデルに送らずChatGPTへ振り分ける。クリップボードはTkメインスレッドから操作。
- `app/ux.py`・`app/voice_feedback.py`：「ChatGPTに用意」と「貼り付けが必要」を区別し、誤って「送信完了」と報告しない。
- `chrome-extension/background.js`：ChatGPTの**空の入力欄だけ**に下書きを挿入。ユーザーの既存下書きは保持し、送信・回答収集はしない。
- `tests/test_v10_chatgpt_handoff.py`：ネット接続なしの自動テスト。
- `tests_js/chatgpt_handoff.test.js`：下書き保護と非送信のDOMテスト。
