# VoicePilot v0.23.5 — PC誤操作とリリース権限の安全対策

v0.23.4の機能を維持し、特に**別のウィンドウへの誤入力**と**テスト用コードのリリース権限**を強化しました。

- **ウィンドウの固定:** AIが画面を観測した時点のウィンドウを記録し、ショートカット・文字入力・スクロールの実行直前に同じウィンドウか照合します。前面ウィンドウが切り替わっていたり識別できなかったりする場合は、操作をせず停止します。「コピーして」「貼り付けて」などの高速操作でも確認ダイアログの前後で対象が変われば停止します。
- **Webフォームの入力:** 空の入力欄でも、入力イベントで自動保存・送信される場合があります。AIが提案したChromeの文字入力は、内容の既存値に関係なく毎回ユーザーの承認を要求します。認証情報や機密情報の入力欄は引き続き禁止です。承認画面ではプライバシー保護のため入力本文を表示しません。
- **GitHub Actionsの最小権限:** PRのPython・JavaScriptテストとZIP構築はリポジトリ読み取り権限だけで行い、リリース公開だけを独立したジョブで実行します。公開処理にはテスト成功とmainの最新コミットであることが必要です。
- **バージョン整合:** Chrome拡張のバージョンを`0.23.5`に合わせ、`VERSION`との不一致があればZIP構築を失敗させます。これにより異なるバージョンの組合せを誤公開しません。
- **回帰テスト:** 対象切替時の入力阻止、空欄へのWeb入力承認、危険な欄の拒否、読み取り専用CI、バージョン不一致を自動検証します。

**限界:** Windowsの前面状態の確認と実際の入力は原子的な単一操作ではありません。入力開始後のOS側のウィンドウ切替を完全には防げません。承認ダイアログは入力本文を表示しないため、生成された文章の内容確認は実際のアプリ画面でも行ってください。GitHub release ZIPは完全なコード署名機構ではなく、GitHubアカウント・CI自体への侵害に対する保証ではありません。実際のPCで安全を確証したものではありません。

# VoicePilot v0.23.4 — 操作時間・CPU時間・メモリの任意診断

v0.23.3のWindows全体操作、ローカルWhisper/Ollama、Chrome拡張、自動更新、安全確認を維持したまま、性能改善の前提となる実測機能と、アイドル時のメモリ解放を調整しました。

## 使い方

VoicePilotを起動し、**「設定」→「性能診断（処理時間・CPU時間・メモリのみ）」**にチェックを入れ、通常どおり音声またはテキストで操作します。操作ログに数値だけの診断行が追加されます（既存の操作ログ自体は従来どおりです）。初期状態はオフで、計測は利用者が有効にした場合だけ実行します。

- **音声**：録音終了から処理終了までの合計時間、Whisperの認識時間（初回モデルロードを含み得る）、操作処理時間を分離して表示します。「話し始めから」の時間ではありません。指示待ちのユーザー確認時間やネットワーク待機は合計・操作処理時間に含まれます。
- **テキスト**：実行ワーカー開始から終了までの合計時間・操作処理時間を表示します。
- **CPU**：VoicePilotのプロセス全体がその間に消費したCPU処理時間を示します（CPU使用率％ではありません）。
- **メモリ**：WindowsのAPIを使い、開始時点と終了時点のVoicePilotプロセスのWorking Set（常駐メモリ）を表示します。ピーク値ではなく、**OllamaやChromeなど外部プロセスの使用量は含みません**。値を取得できない場合は「メモリ計測不可」です。

診断は発話本文・音声・URL・ファイル名・画面内容を追加記録・送信しません。CPU/RAMの値は表示中の操作ログにのみ一時保持され、診断専用の履歴ファイルや常時ポーリングはありません。Gemini等の既存のクラウド設定とデータ送信ポリシーは変更していません。

## アイドル時のメモリ

未使用の音声モデルの自動解放までの時間を、`base`・`small`は従来どおり75秒、`medium`は45秒、`large-v3-turbo`は30秒に調整しました。大きなモデルのメモリ保持時間を短くする一方、解放後に再び話すとモデルロードに時間がかかる場合があります。OS・メモリアロケータの事情によりWorking Setが直ちに減るとは限りません。**実機で削減量や速度向上はまだ測定していません。**

Python/JSの自動テストは計測値の計算・許可設定・モデル解放条件などのロジック確認であり、Windows実機のマイク・操作の安全性を保証しません。

# VoicePilot v0.23 — PC操作の対象ずれ・情報漏れ対策とマイク実機診断

v0.22の自動更新・音声・画面理解・自律作業・Chrome拡張を継承しました。今回も機能を増やすより**Windowsでの安全性と検証のしやすさ**を優先しています。

## 修正した3つの危険経路

1. **保護対象ウィンドウのタイトル漏れを防止：** v0.22ではPowerShellや管理ツールのUI要素を読まなくても、タイトルや他のウィンドウ一覧がAIに渡り得ました。v0.23は保護対象・プロセス不明・管理者権限の画面では、ウィンドウのタイトル、一覧、ボタン情報、内部識別子を返しません。そもそも他のウィンドウのタイトル取得を開始しません。

- Python **255件**、Chrome JavaScript **11ファイル**をローカルで確認。GitHub ActionsのWindowsランナーでもテストする構成です。
- 音声のモックテスト、危険なウィンドウのタイトル遮断、画面変更時の破棄、Chrome非前面の入力拒否を追加しました。

# VoicePilot v0.22 — Windowsの安全性検証・低レイヤー操作の保護

v0.21までの機能を維持し、Windows実機でリスクを確認できる診断と、問題のある操作を拒否する仕組みを追加しました。通常の機能追加よりも**データ保護と停止・誤操作防止**を優先した更新です。

## 今回修正した問題

- **Chrome偽装対策**：ウィンドウタイトルに「Chrome」を含むだけではChromeとは判定しません。Windows APIでフォアグラウンドの実行ファイル名が `chrome.exe` と確認できた場合のみChrome向け操作に振り分けます。取得できない場合はChrome扱いしません。
- **管理者権限を禁止**：VoicePilot本体を管理者として起動すると、GUI開始前に停止します。PCへの合成キー・マウス入力も管理者として動作する場合は拒否します。権限の判定に失敗した場合も拒否します。
- **保護対象画面の情報取得を拒否**：PowerShell、cmd、管理ツールなど対象プロセスを確認できない画面について、AIにスクリーンショットやUI要素を渡す処理を拒否。画面の撮影中に他のウィンドウへ切り替わった場合は画像を破棄します。
- **試験対象の限定**：ファイル移動・名前変更・同名上書き拒否の実地テストは、その場で作る一時フォルダ内だけで行います。デスクトップ・ドキュメント・ダウンロード内の個人ファイルはテスト対象にしません。

## 自分のWindows PCで安全診断を実行する

1. VoicePilotを管理者権限ではなく通常のユーザーとして起動する。最初のセットアップには `setup_and_run.bat` を使用。
2. VoicePilotを終了してから、`run_tests.bat` をダブルクリックする。**Pythonの回帰テスト、Chrome側のテスト、Windowsの安全診断**が実行されます。Node.jsがない場合はChrome側のテストがスキップされます。
3. 安全診断が終わると、**任意のメモ帳入力テスト**を実行するか聞かれます。実施しない場合は `N` を選択してください。
4. `Y` を選択した場合、さらに `YES` を明示入力したときだけテスト用の空のメモ帳を開きます。案内に従ってテスト文書の本文にカーソルを置きます。7秒後にウィンドウ・プロセス・カーソルを確認できた場合のみ、特殊な記号を含む短いテスト文章を入力します。**保存・削除・マウスクリック・システム設定変更はしません。**
5. 画面の記号がそのまま入力されたか本人が確認してください。入力欄を正しく確認できなかった場合は安全のためテストをスキップします。

`tests/windows_safety_check.py` は引数なしで起動すれば**画面操作なしの診断だけ**を行います。診断の表示はテスト名と PASS/FAIL、OS種別のみで、個人のファイル名・画面・録音・APIキーを表示しません。クラウドには送信しません。テストはユーザーの同意なしにアプリを起動しません。

| 対象 | 確認方法 | 判定範囲 |

# VoicePilot v0.21 — 確認付きの長い作業とPC操作安全監査

**v0.20の音声・Chrome・Windows操作・自動更新は維持し、長い作業の実行を明示的な選択制にしました。** 無料ローカルOllama/Whisperが既定で、新しい有料APIや管理者権限は要求しません。

## 使い方

1. メイン画面の指示欄に目標を入力する。最初はメモ帳や練習用フォルダを使い、個人データや機密情報のある画面では実験しない。
2. 通常の「実行」ではなく、**「長い作業（確認付き）」** ボタンを押す。開始前の確認ダイアログで明示的に承認する。
3. AIが画面観測→許可済みの操作→結果確認を繰り返す。**最大28回の計画・観測ステップ、最大12回のPC状態を変える操作、最大240秒**。おおむね6操作ごとに続行確認を求める。保存・投稿・ファイル移動・座標クリック・アプリ起動などは必要に応じて個別承認を要求する。
4. 結果が確認できない操作、例外、キャンセル、上限到達時には作業を停止。**不確かな操作を自動で再実行しない**。作業ログは操作名と状態だけをRAMに保持し、元の指示や入力文章を永続保存しない。
5. 「ハンズフリー開始」済みなら既存の「待って」「続けて」「やめて」で操作境界の一時停止・再開・中止が可能。GUIの停止ボタンや `Ctrl+Alt+Esc` も有効。

**制限：** これは安全制限付きの長めの操作ループであり、無制限の自律エージェントではありません。任意のコード実行・シェル・ファイル削除・任意のファイル内容書換えは未対応です。PDF本文を直接解析してWordファイルを生成するなど、未実装の操作は実行できません。アプリを終了した後の自動タスク復元、実行済み操作の完全な巻き戻しにも対応していません。

## 同時に行った安全監査・対策

| 調査したリスク | 対策とテスト |
|---|---|
| AIが `^s`、`{ENTER}` などを文字入力して意図しないホットキーを実行 | `windows_type` はUI Automationで**カーソルと入力先を確認**してからUnicode文字として送信。制御文字を拒否。UIA非対応の入力欄は安全停止 |

| ローカル管理画面への迂回アクセス | `127.1`、整数IPv4、16進IPv4など、ブラウザ固有の数値IP解釈も拒否 |
| ファイル上書き・リンク経由の操作 | 対象をユーザーの既定フォルダと許可拡張子に制限。シンボリックリンク、既存同名ファイルへの上書きを拒否。ファイル移動・名前変更は個別承認 |
| 長時間タスクの暴走・同じクリックの繰り返し | 時間・操作数・確認回数を制限し、結果不明の副作用操作を繰り返さず停止。一定操作後に画面確認を要求 |
| 公開更新ファイルによる破損 | 既存のGitHub Release SHA-256照合・ZIPパス検証・旧版復元を維持 |

**テスト方法：** Linux環境のモック/一時フォルダ/仮想画面で、危険な入力・ショートカット・URL・上書き・停止/確認拒否・タスク上限を検証。GitHub ActionsのWindowsランナーでもユニットテストを実施する。これらのテストでは実際のユーザーPCのファイル削除、キー入力、管理者権限の取得は行いません。

**残るリスク（重要）：** Windows全体を操作するアプリである以上、誤ったクリックや、正規アプリへの不適切な入力まで完全には防げません。Webサイトの文章やAIの判断に誘導される可能性も残ります。GitHub Releaseのハッシュ確認は**電子署名による作者の真正性保証ではなく**、リポジトリ自体が侵害されれば悪意ある更新が配布され得ます。音声の誤認識や、既に始まった外部操作を完全に取り消せない問題も残ります。**Windowsの実機でのマイク・UI Automation・権限境界は未検証**のため、日常使用や重要データの無人操作に対して安全を保証するものではありません。

検証を始める際は、管理者として実行せず、練習用のWindowsユーザーまたはVMで、空のメモ帳・ダミーファイルだけを対象にしてください。不具合があれば `Ctrl+Alt+Esc` で中止し、手動で状態を確認してください。変更の巻き戻しが必ず成功するわけではありません。

# VoicePilot v0.19 — 操作中の音声割り込みと録音終了判定の修正

**v0.18までのWindowsアプリ・Chrome拡張・無料のWhisper/Ollama・自動更新を維持した改修です。** 新しい有料API、ウェイクワード常時待受モデルは追加していません。

## 新機能

「ハンズフリー開始」を押した後、VoicePilotがPCを操作している間も短い停止指示を聞き取ります。

- **「待って」**：次の操作の実行前に一時停止。進行中の処理を即時中断・巻き戻しするわけではありません。
- **「続けて」**：保留している作業を再開。何も停止していないときは無視します。
- **「やめて」**：現在の作業を中止要求。ハンズフリーの待受は継続し、作業終了後に次の指示を受け付けます。
- **「ハンズフリー終了」**：作業の中止を要求して連続待受も終了。

**マイクの動作**：通常の発話が認識されてPC操作を始めると、短い割り込み指示専用のマイクに切り替えます。無音は直近約2秒だけ保存し、長い発話・雑音は操作として実行しません。Whisperは既存のローカルモデルを再利用します。音声ファイルは保存しません。ハンズフリーを明示的に開始していないときは動きません。

**安全上の限界**：音声から割り込みを認識するまでに遅延があり、すでに実行が始まったクリックやファイル操作、通信は取り消せません。画面の操作結果を確認し、必要なら停止ボタンまたは Ctrl+Alt+Esc を使ってください。一時停止は120秒で自動的に中止となります。PCから流れる動画音声や他人の発話で誤って止まる可能性もあります。画面を見ずに重要な操作を任せないでください。ハンズフリー開始ボタンを押さない通常モードではバックグラウンドの割り込みマイクは起動しません。

## 同時に修正した不具合

v0.18の `Microphone.activity()` は `speech_elapsed` を返していなかったため、無音終了条件が正しく評価されない場合がありました。v0.19では実際の発話開始からの経過時間を返すように修正しています。

## テストと配布

Pythonユニットテスト、JavaScriptテストとGitHub Actions上のWindowsテストで動作確認します。**実機のマイクでの割り込み反応時間と停止成功率は未測定です。** 最新の安定版Releaseから更新される設計ですが、Chrome拡張の再読み込みが必要になる場合があります。

# VoicePilot v0.18.0 — ハンズフリー連続対話

**既存のv0.17のWindows/Chrome操作・音声タイピング・自動更新・安全確認を維持した更新です。**

## できること

1. アプリの「ハンズフリー開始」を**1回押す**と、声を検出する待受を開始します。ミニ画面では「連続ON」。
2. 「Chromeを開いて」→（操作終了）→「下にスクロールして」のように、**毎回ショートカットを押さず**に別の指示を続けられます。
3. 発話後の約1.4秒の無音で音声を確定。Whisperで日本語認識し、従来のAI・PC操作・確認機構へ渡します。
4. 音声認識中・PC操作中・VoicePilot自身の読み上げ中は**マイクを閉じます**。終了したら再度待受に戻ります。
5. 「ハンズフリー終了」「連続対話終了」「聞き取りを止めて」と発話するか、ボタンまたは停止ショートカットで終了できます。
6. **認識された発話が3分間なければ自動終了**。起動時には自動でマイクをオンにしません。
7. v0.17の文章入力モードと併用でき、連続発話で文字を追記できます。入力中は従来どおり機密情報をログへ残しません。

## 操作手順（最初の一回）

- Windowsアプリで「ハンズフリー開始」を押す。声が聞き取れると録音が自動終了して処理が始まります。
- 次の指示は、処理完了後に「聞いています」と表示されたらそのまま話します。
- 終了時は「ハンズフリー終了」と話すか「■ ハンズフリー終了」を押します。緊急の操作中止は従来どおり `Ctrl + Alt + Esc` です。
- 音声フィードバックの後に少し間を置いて録音を開始し、VoicePilotの声を拾い直さないようにします。

## 設計・安全性・制約

- 追加課金のある音声APIを使わず、従来のfaster-whisper/ローカルOllamaを再利用します。
- 常時Whisperを推論させるのではなく、既存の**音量ベースの発話検出**を用いて音声区間を切り出します。Sileroなどの学習済みVADやウェイクワード検出は**未実装**です。
- 何分も無音が続いても録音データは直近約2秒だけを保持します。誤った録音タイマーの再利用は世代番号で防ぎます。
- 明示的に開始したセッション内では周囲の会話が指示と誤認識される場合があるため、重要操作は画面確認と従来の承認を使用してください。
- **操作実行中の音声による割り込みは未対応**です。処理中は意図的にマイクを止めています。中止には停止ボタン・ホットキーを使ってください。
- ほかのアプリの音声は自動的に除外できません。スピーカーから声が流れる環境では、イヤホンやヘッドセットをおすすめします。
- Windows実機のマイク、音声認識精度、CPU使用量、Word/VS Codeでの長時間運用はまだ確認できていません。

## 検証

Linux環境でPythonユニットテスト182件と、従来のChrome疑似DOMのJavaScriptテスト10ファイルを通過。仮想ディスプレイで通常画面とミニ画面のハンズフリー操作ボタン表示を確認。公開時にはGitHub ActionsのWindowsテストの結果を優先して判断してください。

4. Chromeの `chrome://extensions/` を開き、旧拡張機能を無効化して、このフォルダの `chrome-extension` を読み込んでください。接続コードはWindows側アプリからコピーします。
5. `Ctrl + Alt + Space` で音声入力、`Ctrl + Alt + Esc` で中止。ChromeやWindowsの操作、ChatGPTへの下書き受け渡しはこれまでどおりです。

## 精度を測るための実機チェック

次の短い操作を、**意図どおりに成功したか／誤操作したか／何秒かかったか**で測ってください。コード上のテストだけでは日本語認識精度を証明できません。

| テスト | 合格の条件 |
|---|---|
| 無音で録音 | AIが勝手に操作しない |
| 小声で「メモ帳を開いて」 | 指示を取りこぼさず、メモ帳を起動 |
| 「Chromeを開いて」 | 別ブラウザを開かずChromeを起動 |
| 同名タブが2つある状態で切替 | 勝手に一方を選ばず確認 |
| ページ内ボタンが動的に変化 | 古い対象をクリックしない |
| Web入力欄を選択 | ラベルのある欄に正しく入力 |
| ChatGPTで下にスクロール | ページ内の会話領域が動く |
| 長めの指示の途中で中止 | 中止後の新規操作が実行されない |

**検証済み:** Pythonユニットテスト109件、JavaScript疑似DOMテスト、構文確認。
**未検証:** Windows実機の音声認識のWER、操作成功率、処理速度、CPU/RAM利用量、一般のWebサイトとの組合せ。追加処理の一部は精度向上の代わりにわずかな負荷や待ち時間を伴う場合があります。

# VoicePilot v0.10 — ChatGPT Web連携（Codex・Work利用枠を使わないモード）

VoicePilot v0.9の既存コードを引き継ぎ、**ChatGPTのWeb画面に質問を渡す機能**を追加しました。従来のWindows/Chrome音声操作、Ollama・Gemini切替、音声読み上げは維持します。

> **重要:** この連携は **ChatGPTのWeb画面に「下書き」を用意するだけ**です。送信は利用者自身が確認して行います。ChatGPTの回答をVoicePilotが自動取得・操作に反映する機能はありません。ChatGPTアカウントの認証情報をVoicePilotに渡す必要はありません。Windows実機の統合テストは未実施です。

## 設計の理由：Codex/Work枠を温存する

2026年11月時点、OpenAI公式の `Sign in with ChatGPT` を使って自作アプリから直接モデルに推論を依頼すると、**ChatGPTのWork/Codexと共通の利用枠または承認済みクレジット**が使われます。今回の要求は「なるべくCodex・Workの利用枠を使わない」なので、この認証方式を今回は実装していません。

- **PC操作の判断**：従来どおりOllama（完全ローカル、追加API料金なし）／任意のGemini（無料枠には上限あり）を使用。
- **ChatGPTへの相談**：ChatGPTのWeb画面を開き、ユーザーが明示的に話した／入力した文章を下書きにセット。送信は利用者本人が行う。
- **VoicePilotがChatGPTのAPI・Codex・Workを呼び出す処理**：**なし**。
- 通常のChatGPTの会話にも、ご利用プランの通常の利用制限はあります。VoicePilotがWork/CodexのAPI利用枠を消費しない、という意味です。

参考： [OpenAI公式 — 他のアプリでChatGPTプランを使う場合の枠](https://help.openai.com/en/articles/20001542-using-your-chatgpt-plan-in-other-apps-and-sites)

## 使い方

### A. 声で直接ChatGPTに質問を渡す

1. WindowsでVoicePilotを起動し、`Ctrl + Alt + Space` で話す。
2. 「**チャッピーにPythonの例外処理を教えて**」または「**ChatGPTでこの式を解説して**」などと話す。
3. Chrome拡張が接続されていれば、ChatGPTのタブを開き、**既存の下書きが空の場合のみ**、質問を入力欄に用意します。
4. **画面で質問を確認し、自分で送信**してください。VoicePilotは回答を勝手に取得しません。

「**ChatGPTを開いて**」ならページだけ開きます。

### B. テキスト入力欄から渡す

1. VoicePilotの「認識した指示」欄に質問を書く（音声認識後の文章を修正してもOK）。
2. 通常の `実行` ではなく **`ChatGPTへ`** を押す。
3. Chrome上の下書きを確認して送信する。

`ChatGPTへ` ボタンを押した場合は、先頭に「チャッピーに」を付けなくても渡せます。

### C. Chrome拡張が未接続・ログイン待ち・下書きが埋まっている場合

- 文章を**クリップボードにコピー**してChatGPTを開きます（既存の下書きは上書きしません）。
- ChatGPT入力欄に貼り付け、内容を確認して送信してください。
- ChatGPTのUI変更などで入力欄を見つけられない場合にも、この安全な代替操作を使用します。

## 初回セットアップ（Windows 11）

1. ZIPを展開し、`VoicePilot-v0.11` フォルダを用意。旧バージョンは削除せず、両方を同時起動しない。
2. [Python 3.11](https://www.python.org/downloads/) と必要に応じて [Ollama](https://ollama.com/) をインストール。
3. ローカルAIで通常のPC操作も行うなら、`ollama pull gemma3:4b` を一度実行しOllamaを起動。
4. `setup_and_run.bat` を実行。初回はライブラリをインストールし、初回音声認識時にWhisperモデルをダウンロードします。
5. Chromeで `chrome://extensions/` を開き、デベロッパーモードを有効にして、同梱の `chrome-extension` を「パッケージ化されていない拡張機能を読み込む」で追加。
6. 拡張機能ポップアップにVoicePilotの「接続コード」を入力して接続。**旧バージョンのVoicePilot拡張機能は無効に**してください。
7. ChatGPTのWebサイトには、必要に応じて通常のブラウザ操作でログイン。

拡張機能を使わなくても、「ブラウザを開く + 質問をコピーする」手動連携は使えます。

## プライバシー・動作の制限

- ChatGPTのログイン情報やCookie、アカウントトークンをVoicePilotは取得・保存しません。
- ChatGPTへの**送信ボタンは自動的に押しません**。回答の自動抽出・スクレイピングも追加しません。
- PC上の画面全体・ファイル・クリップボードの内容を、**暗黙にChatGPTへ送信することはありません**。明示的に入力した質問文のみ下書きに渡します。
- Chrome拡張には、従来のPC操作のために `<all_urls>` の閲覧権限があります。信頼できるサイトでのみ使い、不用意に入力されたパスワードやファイルを操作しない設計を維持しています。
- ChromeのUIが変更された場合、文章が自動入力できないことがあります。その場合はクリップボードにコピーされるので、手動で貼り付けてください。
- 音声によるPC操作は、依然として通常の権限・アプリのUIに制限されます。
- 実機でのChatGPT画面入力、発話認識精度、CPU/RAM負荷は未検証です。

## 新規・変更したコード

- `app/chatgpt_handoff.py`：明示的な音声指示の判別、Chromeへの受け渡し、クリップボードへの安全なフォールバック。
- `app/main.py`：テキスト欄に `ChatGPTへ` ボタン追加。音声指示もモデルに送らずChatGPTへ振り分ける。クリップボードはTkメインスレッドから操作。
- `app/ux.py`・`app/voice_feedback.py`：「ChatGPTに用意」と「貼り付けが必要」を区別し、誤って「送信完了」と報告しない。
- `chrome-extension/background.js`：ChatGPTの**空の入力欄だけ**に下書きを挿入。ユーザーの既存下書きは保持し、送信・回答収集はしない。
- `tests/test_v10_chatgpt_handoff.py`：ネット接続なしの自動テスト。
- `tests_js/chatgpt_handoff.test.js`：下書き保護と非送信のDOMテスト。
